# Retro Library — инструкция

Локальный сервис для библиотеки RetroArch на Apple TV. Игры хранятся на NAS, а в плейлисты Apple TV попадают выбранные записи. [Установка Docker](../README.md#quick-start), [установка TrueNAS](truenas.md).

## Добавление и оформление

1. Откройте **Добавить файлы**, выберите систему и ROM. Для PlayStation загружайте BIN вместе с CUE. RAR/7z сначала распакуйте.
2. Галочка **Синхронизировать добавленные игры с Apple TV** определяет первоначальный выбор.
3. В фоне запускается поиск по Libretro: CRC32, затем точное нормализованное название. Обложка, скриншот и титульный экран сохраняются в структуре RetroArch. Каноническое название применяется одновременно к карточке, плейлисту и именам обложек; пометка русского перевода сохраняется. Файлы ROM не переименовываются. Свои обложки не перезаписываются.
4. Нажмите на карточку игры: там доступны год, жанр, разработчик, издатель, описание и источники. Если совпадение неоднозначно, выберите точную игру из предложений. Кнопка повторного поиска позволяет повторить запрос после сетевой ошибки.

Недостающие год, жанр, разработчик и издатель заполняются из Wikidata по записи, связанной с найденной статьёй Википедии. Учитываются указанные источником ограничения по платформе; существующие значения Libretro сохраняются. Год — самый ранний доступный год выпуска среди подходящих записей. Если источник не содержит сведений, поле остаётся пустым. После обновления старые карточки автоматически проходят дополнение в фоне; повторная загрузка ROM не нужна.

Если подходящей статьи нет, сервис ищет точное название или псевдоним напрямую в Wikidata и проверяет платформу. Неоднозначное совпадение автоматически не выбирается. Для известных различий между портами используются проверенные поправки из `metadata_corrections.json`: у каждой есть источник, платформа и объяснение.

Неполная карточка получает статус **Сведения неполные**, список пропусков и дату следующего поиска. Недостающие сведения проверяются снова через неделю; после ошибки сети — через час, с увеличением интервала до суток при повторных ошибках. Очередь проверяется каждую минуту. Перезапуск сохраняет график повторов и ручной выбор игры. Если достоверных данных нет, сервис сообщает об этом, а не подставляет выдуманные значения.

ROM и BIOS не отправляются во внешние сервисы. Википедия и Wikidata получают поисковые запросы с названиями игр, Wikidata также получает идентификаторы записей; каталоги и изображения загружаются с GitHub/Libretro.

## Выбор для Apple TV

Отмечайте **На Apple TV** на карточках. Фильтр по системе и поиск работают вместе с кнопками **Выбрать показанные** и **Снять выбор**.

Полная коллекция остаётся на NAS. Снятая игра исчезает из создаваемого плейлиста устройства и перестаёт автоматически восстанавливаться. Уже загруженные файлы с Apple TV не удаляются. Общие дорожки выбранных игр и BIOS продолжают использоваться.

RetroArch должен быть открыт. По умолчанию проверка проходит раз в 60 секунд. После изменения плейлиста может потребоваться открыть его заново. Отличающиеся существующие файлы показываются в разделе **BIOS и файлы** и не перезаписываются автоматически.

## Резервные копии

- **Создать резервную копию** собирает ROM, BIOS, плейлисты, оформление, метаданные и доступные сохранения. Архив проверяется по SHA-256.
- **Скачать архив** позволяет сохранить TAR на компьютер или внешний диск. Если браузер скачивает в Downloads, переместите файл или включите запрос папки при скачивании.
- **Восстановить** сначала проверяет архив и показывает число изменений. Текущие версии заменяемых файлов сохраняются отдельно.
- **Загрузить TAR с внешнего диска** импортирует ранее сохранённую копию.
- **Удалить** удаляет только выбранный архив после подтверждения. Игры и сохранения в рабочей библиотеке не затрагиваются. Отмены удаления архива нет.

Возврат сохранений на Apple TV включается отдельно и может откатить прогресс. Сначала создаётся копия текущих файлов. Подробнее: [резервное копирование и восстановление](backup-recovery.md).

## Доступ

Это UI для доверенной домашней сети без учётных записей. Не публикуйте его напрямую в Интернет. У каждого пользователя с доступом к UI есть возможность загружать файлы, создавать/удалять архивы и запускать восстановление.
